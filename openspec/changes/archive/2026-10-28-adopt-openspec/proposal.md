# Proposal

## Why

Planning in this module is split between Agent OS (`agent-os/standards/`, `agent-os/specs/`, `.claude/commands/agent-os/`) and a leftover OpenSpec install for GitHub Copilot (`.github/prompts/opsx-*.prompt.md`) that has no `openspec/` directory behind it. The Agent OS standards are an older, unversioned copy of the rules now published as pinned OpenSpec stores, and sibling modules (vault, keycloak, gitlab-management) already moved to OpenSpec. Moving outscale-compute aligns it with them and gives the next changes a baseline contract to write delta specs against.

## What Changes

- Remove Agent OS: `agent-os/` (standards and the 2026-02-07 module spec) and `.claude/commands/agent-os/` (5 commands). The standards are replaced by the `quality`, `repository` and `terraform` OpenSpec stores referenced from `openspec/config.yaml`.
- Remove the legacy OpenSpec prompt files `.github/prompts/opsx-*.prompt.md`; they are replaced by the `openspec-*` skills for Claude Code (`.claude/skills/`) and OpenCode (`.opencode/skills/`).
- Configure `openspec/config.yaml` (stores pinned to tags, outscale-compute `context`, per-artifact `rules` and `operations` guidance) and add `AGENTS.md` and `CLAUDE.md`.
- Write the baseline capability specs under `openspec/specs/`, describing the module **as released today**.
- Tooling: pin the `openspec` CLI (and node) in `mise.toml`, add `spec-validate` and `spec-setup` tasks, add `scripts/openspec-setup.sh`, and validate specs in CI through `.gitlab/specs.yml` (job `validate:specs`).
- README "Contributing" points to the OpenSpec workflow.
- No change to any `.tf` file, input, output or resource: semver **patch**, shipped with the next tag. `CHANGELOG.md` stays generated by git-cliff.

## Capabilities

### New Capabilities
- `module-contract`: supported tooling and provider, no provider/backend blocks, required inputs and their validations, common tags, the output set.
- `vms`: role map flattening, naming, tags, networking, boot options, block devices and per-role public IPs.
- `security-groups`: optional security groups and inbound/outbound rules referenced by key from VMs.
- `keypair`: optional SSH keypair with a sensitive public key.
- `volumes`: additional volumes created and linked per VM instance.
- `flexible-gpus`: optional flexible GPUs allocated and linked per VM of a role.

## Impact

- Removed: `agent-os/`, `.claude/commands/agent-os/`, `.github/prompts/opsx-*.prompt.md`.
- Added: `AGENTS.md`, `CLAUDE.md`, `.claude/skills/openspec-*`, `.opencode/skills/openspec-*`, `openspec/specs/*/spec.md` (on archive), `scripts/openspec-setup.sh`, `.gitlab/specs.yml`.
- Modified: `openspec/config.yaml`, `mise.toml` (openspec and node pins, two tasks), `.gitlab-ci.yml` (include), `.gitlab/global.yml` (`OPENSPEC_VERSION`), `.gitlab/pre-commit.yml` (cache keys), README "Contributing".
- Contributors need the stores registered once per machine (`mise run spec-setup`); CI needs no store, it only validates `openspec/`.
- Module consumers: none.
