# Proposal

## Why

The module cannot express three provider arguments that matter for a hardened deployment: removing the allow-all outbound rule Outscale adds to every new security group, keeping a final snapshot when a volume is destroyed, and disabling the source/destination check on a VM. Callers currently work around the first one outside the module. All three arguments already exist in provider 1.8.0, so no provider bump is needed.

## What Changes

- Add optional `remove_default_outbound_rule` (bool, default `null`) to each entry of `security_groups`.
- Add optional `termination_snapshot_name` (string, default `null`) to each entry of a role's `volumes`.
- Add optional `is_source_dest_checked` (bool, default `null`) to each role of `vms`.
- Every new attribute is opt-in: when `null` the module omits the argument, so existing callers see no diff and the second plan stays empty. No input, output, default or resource address changes. **No breaking change.**
- Update `examples/complete/` to show the secure settings, add unit tests, and document the new attributes (README tables are regenerated by terraform-docs).

Semver classification (`terraform-versioning`): **minor**. New `optional()` attributes with a `null` default are a minor bump. The provider pin stays `~> 1.8`, so no floor is raised.

Input shape changes (all additive, none alters an existing type, default or meaning):

| Input | New attribute | Type | Default |
| --- | --- | --- | --- |
| `security_groups` | `remove_default_outbound_rule` | `optional(bool)` | `null` |
| `vms` | `is_source_dest_checked` | `optional(bool)` | `null` |
| `vms[*].volumes` | `termination_snapshot_name` | `optional(string)` | `null` |

What lands in state: booleans and a snapshot name only; none is secret-bearing, so `terraform-security` write-only arguments do not apply and `SECURITY.md` needs no new row. The final snapshot taken at volume destruction is a provider-side object outside Terraform state.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `security-groups`: a group can opt in to removing the default allow-all outbound rule.
- `volumes`: a volume can opt in to a named snapshot taken when it is destroyed.
- `vms`: a role can opt in to setting the source/destination check; a new requirement is added next to "VM definition fields and defaults".

## Impact

- Code: `variables.tf` (object types of `vms` and `security_groups`), `locals.tf` (pass the new fields through the flattening), `main.tf` (three resources), `tests/main.tftest.hcl`, `examples/complete/`, README (terraform-docs block only, via pre-commit), `TESTING.md` if it lists tests.
- Compatibility: Terraform/OpenTofu `>= 1.5` and `outscale/outscale ~> 1.8` unchanged.
- Standards applied: `terraform-versioning`, `terraform-variables`, `terraform-security` (network defaults), `terraform-code-style` (no perpetual diff), `quality-security` (safe defaults, no silent weakening).
